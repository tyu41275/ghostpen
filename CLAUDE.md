# ghostpen

Personal developer blog by Tim Yu. Built on Next.js 14 + Contentlayer2 + Tailwind CSS, deployed on Vercel. Originally forked from Tailwind Nextjs Starter Blog v2.

GitHub: tyu41275/ghostpen

## Architecture

```
app/                    # Next.js 14 app directory (pages, layouts, API routes)
  blog/                 # Blog listing and individual post pages
  about/                # About page
  tags/                 # Tag listing and per-tag post pages
  projects/             # Projects page
data/
  blog/                 # .mdx blog posts (YAML frontmatter + MDX body)
  authors/              # Author profiles (default.mdx = Tim Yu)
  style-guide.md        # Writing style extracted from existing posts — AI generators MUST follow this. Read the "Anti-Formula Rules" section as binding over the example lists above it: the "Characteristic phrases" list and the rejection criteria describe RANGE, and a generator optimising against them as a checklist produces six near-identical posts (#67-#75; #74 used 7 of the 8 example catchphrases in the guide's own order, against 0-2 for the human posts). The rules cap catchphrase reuse at two, ban the templated Problem/Investigation/Solution/Conclusion header set, and set the length target from the published corpus.
  siteMetadata.js       # Site-wide config (title, URL, analytics, search, comments)
  projectsData.ts       # Projects page content
  headerNavLinks.ts     # Navigation links
  logo.svg              # Site logo
scripts/
  postbuild.mjs         # RSS generation — runs automatically after `next build` via the build script
  rss.mjs               # RSS feed generator — called by postbuild.mjs to create feed.xml
contentlayer.config.ts  # Content schema definition — Contentlayer2 reads this to type-check and process all .mdx files
layouts/                # Page layout components (PostLayout, ListLayout, AuthorLayout)
components/             # Reusable React components (Tag, SearchButton, etc.)
css/                    # Global styles (Tailwind base + custom)
public/
  static/images/        # Blog post images, organized by slug (e.g., public/static/images/<slug>/)
```

## Frontmatter schema

Defined in `contentlayer.config.ts`. Every `.mdx` file in `data/blog/` must include YAML frontmatter with these fields:

| Field          | Type            | Required | Default | Purpose                                                                                |
| -------------- | --------------- | -------- | ------- | -------------------------------------------------------------------------------------- |
| `title`        | string          | yes      | —       | Post title displayed on the page and in listings                                       |
| `date`         | date            | yes      | —       | Publication date (ISO format, e.g., `2026-03-20`)                                      |
| `lastmod`      | date            | no       | —       | Last modified date — shown when different from `date`. Leave the line out rather than empty: an empty `lastmod` drops the post from the build (ghostpen#108) |
| `tags`         | list of strings | no       | `[]`    | Categorization tags — lowercase, hyphen-separated (e.g., `sitecore`, `xm-cloud`)       |
| `draft`        | boolean         | no       | `false` | When `true`, post is excluded from production builds                                   |
| `summary`      | string          | no       | —       | Short description for listings and SEO meta tags                                       |
| `images`       | json            | no       | —       | Array of image paths for Open Graph / structured data                                  |
| `authors`      | list of strings | no       | —       | Author slugs referencing files in `data/authors/` (default: `default` = Tim Yu)        |
| `layout`       | string          | no       | —       | Override the default post layout component (e.g., `PostBanner`)                        |
| `bibliography` | string          | no       | —       | Path to a `.bib` file for academic citations via rehype-citation                       |
| `canonicalUrl` | string          | no       | —       | Canonical URL for cross-posted content — tells search engines where the original lives |
| `aiGenerated`  | boolean         | no       | `false` | Flags AI-generated content — AI posts MUST set this to `true` for transparency         |

### Computed fields (auto-generated by Contentlayer2, not set in frontmatter)

- `readingTime` — estimated reading time calculated from word count
- `slug` — URL slug derived from the file path
- `path` — full content path used for routing
- `filePath` — source file path for internal reference
- `toc` — table of contents extracted from headings
- `structuredData` — JSON-LD schema.org BlogPosting for SEO

## Commands

```bash
yarn dev        # Start dev server — uses cross-env to set INIT_CWD for Contentlayer2 path resolution
yarn build      # Production build + RSS generation — runs next build, then postbuild.mjs for feed.xml
yarn lint       # ESLint with auto-fix across all source directories (pages, app, components, lib, layouts, scripts)
yarn serve      # Serve the production build locally — useful for testing the built output before deploy
yarn analyze    # Bundle analysis — sets ANALYZE=true to generate @next/bundle-analyzer report
```

**Package manager**: yarn 3.6.1 (Plug'n'Play disabled — uses `.yarnrc.yml`). Always use `yarn` commands, never `npm`.

## Conventions

### Blog posts

- **Filename**: `<slug>.mdx` in `data/blog/` — the slug becomes the URL path (`/blog/<slug>`)
- **Images**: Place in `public/static/images/<slug>/` — reference as `/static/images/<slug>/filename.png`
- **Tags**: Lowercase, hyphen-separated (e.g., `sitecore`, `xm-cloud`, `azure-paas`)
- **Author**: Use `default` unless adding a guest author (references `data/authors/default.mdx` = Tim Yu)

### AI-generated posts

- MUST set `aiGenerated: true` in frontmatter — marks the post as AI-generated for transparency
- Arrive as a pull request, never a direct commit: the adapter writes `draft: false` in the file because the pull request is the draft, and Publish merges it only after its review approves (`adapter/docs/publishing.md`)
- MUST follow the writing style guide at `data/style-guide.md` (the writer reads it through `draft.styleGuide`) — ensures AI output matches the author's voice and structure

### Mermaid diagrams

- Client-side rendering via the `mermaid` npm package — diagrams render in the browser, no build-time dependencies
- `components/Mermaid.tsx` handles rendering with dark mode support via `next-themes` and error fallback to raw code
- `components/MDXComponents.tsx` intercepts ` ```mermaid ` code blocks via a `pre` override and routes them to the Mermaid component — all other code blocks pass through normally
- Previously used `rehype-mermaid` (build-time SVG) but switched to client-side because Vercel's build environment lacks Chromium

### Code style

- Husky + lint-staged enforce formatting on commit — ESLint fixes JS/TS, Prettier formats all file types
- TypeScript throughout (`.ts`, `.tsx`)
- Tailwind CSS for styling — no custom CSS unless extending Tailwind utilities

## Drafting: the chatter adapter

ghostpen drafts posts as an optional chatter adapter in `adapter/` (Obsidian ADR 0101; see `adapter/docs/adapter.md`). The post-ship hook and the Python generator it ran (`scripts/generate_post.py`, which read Ensemble's artifacts) are retired and removed.

- **Sources:** only what its settings' `sources` block names (`adapter/docs/sources.md`); nothing in code names a machine or a person's folders. `adapter/test/repo-portable.test.ts` fails on a machine-specific path (a drive path, a home or user folder) or a Claude hook in any code file.
- **Ranking and shortlist:** it ranks topics by value on its own before each weekly shortlist (`adapter/docs/ranking.md`; by hand, `node adapter/dist/cli/rank.js <settings>`), shown on its app page, and proposes the shortlist in its channel with Write, Skip and Not yet (`adapter/docs/shortlist.md`).
- **Drafting:** the checks every draft must pass and the writer (`adapter/docs/drafting.md`; `node adapter/dist/cli/draft.js <settings> <id>`). Screenshots are taken with Playwright, masked, and privacy-checked, failing closed.
- **Publishing:** a Write drafts the topic, opens the blog pull request and starts its review; Publish lands it once the review approves and Edit sends changes (`adapter/docs/publishing.md`). Every press carries a reason; each card's thread takes questions and context (`adapter/docs/feedback.md`).
- **Install:** `adapter/scripts/install-host.sh`, or Relay's `adapter/scripts/relay-install.mjs`; it declares the readiness list in chatter's drop-in unless `--readiness off` (`adapter/docs/install.md`).

## Context Scoping

**For blog post content** -> `data/blog/` — MDX posts with YAML frontmatter
**For AI post drafting** -> `adapter/` — the chatter adapter and its service (`adapter/docs/adapter.md`)
**For writing style** -> `data/style-guide.md` — AI generators MUST follow this guide
**For content schema** -> `contentlayer.config.ts` — defines frontmatter fields, computed fields, content processing
**For page routing / layouts** -> `app/` (Next.js app directory) + `layouts/` (page layout components)
**For UI components** -> `components/` — shared React components (Tag, SearchButton, navigation, etc.)
**For styling** -> `css/` + `tailwind.config.js` — Tailwind CSS configuration and global styles
**For site metadata** -> `data/siteMetadata.js` — title, URL, analytics, search, comments config
**For build scripts** -> `scripts/postbuild.mjs` + `scripts/rss.mjs` — RSS generation, post-build tasks

**Ignore**: `node_modules/`, `.next/`, `.contentlayer/`, `yarn.lock`, `.claude/worktrees/`

**When to escalate**: For drafting, ranking or publishing, read `adapter/docs/` first; for chatter's side (the drop-in, readiness, the app page's sign-in), read chatter's docs. For blog styling, layout, content, or Next.js issues, stay local.
